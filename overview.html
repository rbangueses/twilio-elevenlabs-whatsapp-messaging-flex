High Level Overview

Twilio WhatsApp to ElevenLabs to Flex Relay Blueprint

A working pattern for handing an active WhatsApp conversation from an ElevenLabs AI agent to a human on Twilio Flex — without losing the thread, the transcript, or the customer's place in the story.

What it is

A bot-to-human handoff pattern for WhatsApp, not a chatbot demo.

The blueprint connects a Twilio-owned WhatsApp Conversation to an ElevenLabs Conversational AI agent, passes the Conversation SID into the agent session, and gives the agent a webhook tool that creates a Flex Interaction bound to the same Conversation when escalation is needed. The customer keeps typing to the same number — Twilio just quietly replaces the AI with a human.

Containment

Let AI try first

ElevenLabs handles the customer's turns through its Agent WebSocket and delivers text replies back into the same Twilio Conversation. Twilio owns the WhatsApp sender the whole time.

Control

Keep the thread in Twilio

One Conversation SID (CH...) holds every message — bot's and human's — across the whole interaction. Flex agents join the same thread rather than a copied transcript.

Context

Carry the handoff summary

On escalation, the ElevenLabs agent sends summary, intent, reason, customer address, and a handoff ID to the relay, which surfaces them as TaskRouter task attributes for the Flex agent.

This blueprint is a proof-of-concept reference implementation, not a production drop-in. Treat it as a starting point for the architecture and adapt routing, authentication, prompts, observability, security, and compliance controls to your use case.

Why it is useful

Bot-to-human transition without breaking the thread.

Bolting an AI on top of a WhatsApp support number is easy. Making it hand off cleanly to a human when it can't cope — and doing that on the same WhatsApp thread the customer's been typing in — is where most integrations stumble. This blueprint solves that specific hand-off.

1

Preserve the customer thread

The Twilio Conversation (CH...) survives the transition. Bot replies and human replies are siblings in the same thread — the customer never sees a reset.

2

Pass useful context

The Flex agent picking up the task sees the transcript plus a concise summary, intent, and reason produced by the AI on its way out.

3

Route with Flex

Flex Interactions plus TaskRouter route the escalated task to a human worker, with the Conversation attached — the same tools Flex already uses for human-only channels.

Extension point: keep the escalation payload's Flex task attributes short. For larger context, store the full transcript or knowledge lookup externally and pass a compact identifier such as handoffId or conversationSid so the Flex agent's tooling can fetch the details on demand.

How it works

Twilio Conversations at the center. Relay in the middle. ElevenLabs and Flex at the edges.

A small Node relay service listens for Twilio Conversation webhooks, bridges bot turns to ElevenLabs over a WebSocket, and creates a Flex Interaction when the agent invokes the escalate_to_flex tool. TaskRouter events flow back to the relay so its state machine advances as the human agent picks up and later wraps the task.

Runtime loop Conversations + WebSocket + Flex Interactions API
WhatsApp customer Messages your Twilio WhatsApp sender.
ElevenLabs agent Relay bridges the customer turn as user_message.
Escalation tool Agent asks the relay to create a Flex Interaction.
Flex + TaskRouter Task routed to a human, who joins the same Conversation.
Inbound message Twilio Conversations post-event webhook → /webhooks/twilio/conversation. The relay bridges the customer's turn to ElevenLabs and writes the bot reply back into the same Conversation.
Escalation ElevenLabs webhook tool → /webhooks/elevenlabs/escalate-to-flex. The relay creates a Flex Interaction bound to the existing CH... SID.
TaskRouter events Workspace Event Callback → /webhooks/taskrouter/events. Advances the state machine through human_pending → human → closed.

The relay is scoped to WhatsApp today. Twilio Conversations is channel-agnostic, so SMS and webchat are on the roadmap and will slot in behind a per-channel address parser without changing the Flex handoff path.

Optional capabilities

Memory and cross-channel voice compose cleanly on top.

The core relay is scoped to bot-to-Flex on WhatsApp. Once that's working, three add-ons layer on without changing the runtime path — each documented in the README.

Memory

Twilio Conversation Memory

The messaging agent can call a recall tool at the start of a conversation to pull the customer's Profile, including facts extracted from previous voice calls if the same customer's identifiers link to the same Profile.

Voice pairing

WhatsApp Business Calling

Paired with the voice blueprint, a single WhatsApp business number handles both text and voice on the same sender identity. Memory links the two channels for context continuity across the customer's calls and messages.

Roadmap

Multi-channel

Twilio Conversations is channel-agnostic, so SMS and webchat will slot into the same relay with a per-channel address parser and a channel-aware Flex Interaction shape.
